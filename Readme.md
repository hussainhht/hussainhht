## 05 · [GridDominion](https://github.com/hussainhht/GridDominion)

A Rust bot for the Filler programming challenge that evaluates placements and competes for territory using spatial algorithms.

**Rust · Multi-Source BFS · Manhattan Distance · SDL2 · Docker**

- Parses live board and piece input
- Generates legal placements
- Uses **multi-source BFS** to estimate territory control

- Includes match-recording and debugging tools

# Engineering Mindset

The part of software development I enjoy most is when a project stops being just a UI and starts becoming a **system**.

I like thinking about questions such as:

- Where should state live?
- What happens when multiple operations modify the same state?
- What must be persisted before an event is delivered?
- Where should authorization rules be enforced?
- How do you keep payments, memberships, messages, or game state consistent?
- When should I use an abstraction, and when should I understand or build the primitive myself?
- How do algorithms, networking, databases, backend architecture, and UI decisions meet in one working product?

That's the direction I want my work to keep moving toward:

**less demo code, more engineering.**
